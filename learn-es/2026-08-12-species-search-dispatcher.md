# Species Search Dispatcher — Final Learn Entry

## What

The species-search-dispatcher change delivers a complete read-only
species search web app. A FastAPI + SQLite backend exposes the WoRMS
taxonomic cascade through 12 endpoints; a React + Vite + Tailwind
frontend consumes those endpoints through a 6-step dropdown UI plus
12 dispatch URLs per resolved species. The change ships across
seven chained pull requests and closes the species-search-dispatcher
SDD change end-to-end.

## Why

The species-search-dispatcher change replaces the legacy Google
Sheets navigator with a real web app. The cascade UI mirrors the
sheet's six-rank navigation but adds:

- A typed API contract instead of spreadsheet formulas.
- An inclusion-filter UI for extinct / synonyms / uncertain /
  unassigned taxa — the spreadsheet did not surface these
  distinctly.
- A 409 ambiguity picker when the same `(genus, epithet)` pair
  resolves under multiple parent breadcrumbs.
- 12 dispatch URLs per resolved species in a clickable button
  grid (the spreadsheet required copying the species name into
  each source manually).

The design-first workflow (Phase 3) ensures the frontend matches
the captured design before any React code lands. The audit's two
follow-ups (P2 token extraction, P3 system-ui fallback) both ship
in Phase 4.

## How it works

End-to-end flow:

1. The user runs `python -m taxon.import_data <dump> data/taxon.db`
   which builds the SQLite database from the WoRMS text dump.
2. The user runs `python -m taxon.main` to start the FastAPI server.
3. The user runs `cd frontend && npm run dev` to start the Vite
   dev server (proxies `/api` to `:8000`).
4. The Cascade UI mounts; it fires `GET /api/kingdoms` and renders
   the Kingdom dropdown.
5. The user picks Kingdom → Phylum → Class → Order → Family →
   Genus. Each selection fires a `GET /api/{path}/{rank}`
   request; the previous request is aborted via
   `AbortController`.
6. Once the Genus is chosen, `GET /api/{path}/{genus}/species?include=`
   returns the species list. The `include` toggles
   (extinct / synonyms / uncertain / unassigned) widen the result
   set per the inclusion-filters spec.
7. The user clicks a species row; the row dispatches a
   `taxon:select` custom event. App catches it, stores the
   resolved species + breadcrumb, and fires
   `GET /api/{path}/{genus}/{epithet}/links` for the 12 dispatch URLs.
8. The 12-link grid renders. Sci-hub is visually separated
   (red border). Every link opens in a new tab with
   `rel="noopener noreferrer"`.
9. If `GET /api/species/{genus}/{epithet}` returns 409, the
   Ambiguity Picker modal opens with each candidate's full
   breadcrumb. Clicking a candidate updates the resolved species
   and dismisses the modal.

## Deviations and decisions (consolidated)

1. **Two lookup endpoints instead of one.** Full-breadcrumb
   (`/{path}/{genus}/{epithet}`) is always unambiguous (200/404).
   Pair-only (`/api/species/{genus}/{epithet}`) can be ambiguous
   (200/404/409). Both share `SpeciesLookupResponse`.

2. **Pagination cursor uses canonical names, not ids.** Names are
   immutable once captured; ids are not. The tie-breaker on
   `Taxon.name` keeps pagination deterministic.

3. **The `/species` response shape changed from 2B to 2C.** Sub-PR
   2B returned bare `list[TaxonResponse]`; Sub-PR 2C wraps it in
   `{items, next_cursor}`. The cascade UI does not yet exist so no
   client is affected.

4. **AmbiguityCandidate replaced CandidateRef on the wire.**
   Sub-PR 2A defined `CandidateRef(id, breadcrumb)`. Sub-PR 2C
   needed `canonical_name + display_name` so the UI can render
   disambiguation without a second request.

5. **`pathlib.Path` shadowed `fastapi.Path` in router.py.** Aliasing
   to `PathLib` resolved the conflict. Documented in the Phase 2B
   `/learn-es/`.

6. **Pencil MCP server (Pen.app) rejects external tool calls.**
   Discovered during Phase 3. The Pencil CLI (`pen`) bypasses the
   MCP server entirely. The minimal `scripts/pencil_client.py`
   monkey-patch is kept as a debugging reference for future
   external clients.

7. **`encodeURIComponent` is not enough.** The frontend's
   `encodeSegments` helper re-encodes `()`, `!`, `*`, `'` so the
   byte-for-byte match on the backend works.

8. **State machine `generation` counter** as a defensive race guard
   in the cascade.

9. **Vite automatic JSX runtime** — the ESLint config disables
   `react/react-in-jsx-scope` and `react/jsx-uses-react` since the
   Vite runtime doesn't need `import React` in every JSX file.

10. **`system-ui` first in the font stack.** P3 audit follow-up:
    the user's OS font wins before Inter loads.

11. **Custom events for cross-component communication.** SpeciesList
    dispatches `taxon:select` rather than calling a callback prop.
    App catches via `addEventListener`. Keeps SpeciesList purely
    presentational.

12. **Pencil rejected `system-ui` literal** — the Codex agent chose
    Inter + IBM Plex Mono. Documented fallback in CSS.

## Next steps

The species-search-dispatcher change is complete. Future work:

- **Frontend deployment**: serve `frontend/dist/` from the FastAPI
  backend (e.g. via `StaticFiles` mounted at `/`). Not part of
  this change because no hosting target was chosen.
- **Lighthouse a11y audit** on the production build. The cascade
  carries proper ARIA labels, but a Lighthouse run will catch
  edge cases (color contrast in dark mode, focus order across
  the modal).
- **Pagination cursor testing** at the 500-item boundary. Currently
  the contract is pinned by `list_species_page` returning
  `next_cursor` after 500 rows; a 600-row integration test would
  harden the boundary.
- **Performance**: the cascade renders 6 dropdowns + a 12-link
  grid; React.memo on the species row + virtualization for the
  500-item list would help when genera carry hundreds of species.
- **Spec archive**: when the next change touches the same surface,
  archive the species-search-dispatcher specs into
  `openspec/specs/<capability>/spec.md` (the canonical location)
  and remove the change folder.
